# Ironlog — Full Improvement Review (v0.60.0, 2026-09-22)

*Written to be read by someone who isn't a programmer. Each finding says what's going on in plain words, why it matters, and how big the fix is. File references are there so any fix can be found quickly later.*

**Fix sizes:** **Small** = under an hour or two · **Medium** = about an afternoon · **Large** = a multi-day project.

---

## 1. The one-minute version

- **The app is in good shape.** Logging a set is **one tap**, as fast as Strong or Hevy. It stays fast even with 5,000 workouts. The 296 automated tests all pass, and no security holes were found.
- **The biggest problem: the app has five separate "judges".** Five different parts of the app each decide whether one set is better than another, and each uses its own rules. Most of the correctness bugs come from this. They show up mostly on assist machines (assisted pull-up/dip), timed holds (plank, carries) and bodyweight moves.
- **The biggest day-to-day friction is changing the plan mid-workout.** Going heavier means retyping every set. Swapping a machine that's taken costs 4+ taps and puts the new exercise at the bottom. And the app doesn't know a Planet Fitness weight stack goes up by 10–15 lb, not 5.
- **Storage has a ceiling, but it's years away.** The phone holds about 1,700 workouts, which is roughly 8 years at 4 workouts a week per person. Worth fixing eventually; not urgent.
- **An AI coach is possible,** and the cheapest version is almost free to build. Section 9 has the options. The catch is that the home-screen version you actually use can't reach Claude by itself.

## 2. How the app is put together

Think of Ironlog as a small restaurant with four parts:

| Part | What it is | Where it lives |
|---|---|---|
| **The chef** | All the thinking: progression, PRs, workout building, coach notes, trends. Knows nothing about screens. | `src/engine/` (progression, builder, analysis, sync, search) + the exercise list in `src/data/exercises.js` |
| **The dining room** | The screens you see and tap: Today, History, Library, Progress, plus the pop-up sheets. | `src/app/ui-core.js`, `ui-today.js`, `ui-views.js`, `ui-bind.js`, `styles.css`, `template.html` |
| **The pantry** | Where your workouts are kept: on the phone, plus an optional backup to Dropbox (or Claude's database in the Claude version). | `src/app/store.js`, `dropbox.js` |
| **The delivery van** | Packs everything into **one single file** and ships it to three places: the home-screen app (GitHub Pages), the private Claude version, and the public demo. | `build.js` → `docs/`, `dist/` |

**How a set gets logged:**
1. You tap ✓.
2. The dining room updates the set.
3. The pantry saves the in-progress workout on the phone.
4. If backup is on, a copy is queued for Dropbox.
5. The screen is redrawn.
6. When you tap **Finish**, the chef cleans up the workout (drops empty sets, stamps your bodyweight) and it moves from "in progress" into your permanent history.

**One quirk worth knowing:** the four screen files are glued into one big shared space. If two of them ever define something with the same name, one silently replaces the other. It has caused a bug once before. It isn't happening today, and a 10-line safety check would prevent it for good (§8).

## 4. Correctness bugs: the app giving wrong answers

### 4.1 Five judges, one set (the root cause) · High · Large
**What's happening:** the progress chart, the PR board, the live "★ New PR" banner, the coach's "lifts trending up", and the "you've stalled" check each have their **own rulebook** for judging a set. They can contradict each other about the same lift.

**Concrete examples:**
- The stall check scores a bodyweight pull-up × 12 the same as a +10 lb pull-up × 6.
- The live PR check would count a 225 × 0 set as a 225 PR. It's also copy-pasted in two files (`ui-today.js:413`, `ui-bind.js:52`), and it's switched off for assist machines and timed holds because it can't handle them.

**Fix:** one shared "judge" function that every feature asks. This one change also fixes 4.3–4.5 below, and turns on live PR banners for assist machines and planks.
**Files:** `progression.js:114` `setScore`, `analysis.js:323`, `builder.js:314`, `progression.js:167`.

### 4.2 Assisted pull-up/dip: an unassisted rep can't be saved · High · Small
**What's happening:** when you finally do the assisted machine with **zero** assist, the app throws that set away at Finish, even though its own tip told you to try it. The "Add a weight first" check also blocks it before that.
**Fix:** treat 0 assist as a real set (`progression.js:65`, `ui-bind.js:441`).

### 4.3 Assisted lifts: the next workout is built around your easiest set · Med-High · Medium
**What's happening:** on an assist machine, more weight means easier. The planner still treats "most weight" as the top set. Example: last time 50×12, 40×8, 40×8 → next plan 45×9, 35×8, 35×8. That makes your hard sets harder before you've earned it. The wording also says "earns +5 lb" when it should say "less assist".
**Fix:** for assist machines, anchor on the *lowest* assist (`progression.js:218`, `builder.js:24`).

### 4.4 Assisted lifts ignore reps for PRs · Med · Small
**What's happening:** 40 lb assist × 12 and 40 lb assist × 5 count as equal, so a worse, newer set can replace your record. With no bodyweight entered, the trend line is flat at zero.
**Fix:** break ties on reps.

### 4.5 Reps-only moves never show progress · Med · Small
**What's happening:** hanging leg raises, Nordics, ab wheel, back extensions and sissy squats never get a PR, a trend line or a "trending up", no matter how many reps you add. Three features skip them. Yet the stall check *does* count them, so the features disagree.
**Fix:** score these by reps when there's no weight (part of 4.1).

### 4.6 The coach mixes Smith and dumbbell versions of a lift · Med · Small
**What's happening:** switching overhead press from Smith (100) to dumbbells (40) reads as "going down". Every other feature keeps equipment types separate; this one doesn't.
**Fix:** one line (`analysis.js:54`).

### 4.7 Planks: a "recovery" day gives you your hardest hold · Low-Med · Small
**What's happening:** a deload for a timed hold prescribes your *longest* hold. The tips also say "add a rep" instead of "hold longer" (`progression.js:286`, `:303`, `:321`).

### 4.8 Moving a workout's date leaves its set times behind · Low · Small
**What's happening:** my v0.57 "move to another day" shifts the workout but not each set's timestamp, so time-per-muscle stats go wrong for moved workouts.
**Fix:** shift every set's time too (`ui-bind.js:236`).

### 4.9 The CSV can show 0 volume where the app shows real volume · Low · Small
**What's happening:** my v0.60 CSV export doesn't fall back to your current bodyweight the way the History screen does. In edge cases (a workout synced in without a saved bodyweight), bodyweight lifts export as 0.
**Fix:** use the same fallback (`sync.js:146`).

### 4.10 A continued plan can list one exercise twice · Low · Small
**What's happening:** this only happens in a continued plan with 3+ heavy barbell leg/back lifts. The swap helper checks the original list, not the swaps it has already made (`builder.js:98`). It never happened in about 4,000 fresh builds.

## 5. Logging friction: where tracking is slower than it should be

*These were measured by walking through real workouts in the app.*

| Action | Taps today | Verdict |
|---|---|---|
| Log a set at the suggested numbers | 1 | Excellent |
| Log with different reps | 2–3 | Fine |
| Repeat a past workout | 2 | Good |
| **Swap an exercise** | 4+, and it lands at the bottom | Poor |
| **Go heavier on every set** | Retype each set separately | Poor |
| **First-ever workout** | 6 exercises × 20 empty sets | Heavy |

### 5.1 Change one set's weight and the sets below follow · P1 · Small
**Plain words:** change set 1 from 100 to 135, and sets 2–4 become 135 too (unless you've already ticked or edited them). This is the most common friction in the app. Strong does it.

### 5.2 "Replace" button that keeps the exercise's spot · P1 · Small–Medium
**Plain words:** "this machine's taken, give me something similar *right here*." A ⇄ next to the ✕ opens the add sheet already filtered to the same muscle and swaps in place. Hevy has it, and it's the big one for a busy gym.

### 5.3 Each exercise remembers its weight step and its machine setup · P1 · Small–Medium
**The most important item for your wife.**
- **Weight step:** the app assumes every machine goes up by 5 lb (2.5 for isolation), so it can suggest 102.5 lb on a pec deck that only does 100/110. Add "Goes up by: 2.5 / 5 / 10 / 15", remembered per exercise (`progression.js:185`).
- **Setup note:** add a pinned note like "seat 4, pad 3" that shows every time. Today's exercise note only shows *last session's* note.

### 5.4 Move exercises up and down · P2 · Small
Today "Auto-order" is the only way to reorder, and it only appears once there are 3+ exercises.

### 5.5 A gentler first workout · P2 · Small
When there's no history yet, build 4 exercises × 3 sets instead of 6 × 20, with one line: "enter what you lift today; next time it's prefilled."

### 5.6 Tidy the Progress tab · P2 · Small
- **Too much:** the tab has 8 sections, and the question you care most about ("am I getting stronger at X?") sits below four advice cards.
- **New order:** stats → **Your lifts** (the PR list with a small trend arrow) → volume chart → coach notes.
- **Collapse by default:** Time, Recovery and Cardio.
- **Home:** it repeats the Progress tiles, so swap them for one line ("2 workouts this week · 3-wk streak") and give the space to "Last session".

### 5.7 Declutter the exercise card · P3 · Small
- Each card has up to 6 small links next to the ✓ button. Move **Watch demo** and **Note** into the ⓘ sheet.
- Let any set be removed with a swipe, not just the last one.

### 5.8 Small cleanups · P3 · Small
- Hide the debug text at the bottom of Settings ("screen … inset … deficit …").

### What to add, and what NOT to add
**Add:**
- The weight step and setup note (5.3).
- An optional "per side" label on single-arm/single-leg moves, so nobody double-logs.

**Skip:**

| Idea | Why not |
|---|---|
| RPE/RIR (a 1–10 "how hard" score per set) | One more decision on every set for a user who already finds logging hard. The app already adjusts from reps. |
| Tempo | Almost nobody logs it consistently. |
| Drop-set / AMRAP labels | A drop set already logs fine as an extra set. |
| Soreness / sleep / readiness scores | The workout note covers it. Scores nothing acts on are just chores. |
| Supersets | The real benefit is rest-timer pacing, which is a big build for modest gain. Only if you both actually superset. |
| Lock-screen timer / Apple Watch | Not possible for a web app. |

## 6. Couples: you and your wife

**The risk today:** the app has no idea of "who". It has one log, one bodyweight, one profile and one in-progress-workout slot. So:
- **If you share backups:** if she connected to *your* Dropbox (or opened your private Claude link), her workouts would merge into yours. Your PRs, volume and coach notes would all be wrong, and two live workouts would overwrite each other.
- **If she has no backup:** her log lives only on her phone. That's the exact "never lose lifts" fear.

**Do now (no code):**
- She uses **her own phone** with **her own Dropbox** connected and the Machine-gym profile.
- Check that *your* home-screen app has Dropbox connected too: Settings → Cloud backup should say Synced.

**Later, only if wanted (Medium):**
- A "Who's training?" switcher that keeps separate logs on one phone.
- A "share a routine as a code" button, so she can copy your push-day template.

## 8. Code cleanup: making the app easier to change safely

*None of this changes what you see. It makes future features faster to build and less likely to break something.*

### Engine (the chef)
- **Same rule written in many places.**
  - "Which workouts count" is written out 6 times.
  - The assist-machine check is repeated about 10 times.
  - The rest-gap math appears twice.
  - Fix: one shared helper each (Small).
- **Dead code:** `exampleFor`, `PUSH_PATS`/`PULL_PATS`, `LONG_SESSION_MIN`, plus unused inputs (`seed`, `opts.now`) (Small).
- **Hard-to-read functions:** `planWorkout` (70 lines, four early exits) and `personalRecords`. Split into named steps (Medium, easier after 4.1).
- **Stored data means different things per exercise** (Medium–Large, gradual):
  - The "reps" box holds seconds for planks; the "weight" box holds *assist* for assist machines.
  - Numbers are stored sometimes as text, which is why `+st.w||0` appears about 40 times.
  - Fix: store numbers as numbers, and give each exercise one "what do my numbers mean" setting.

### Screens (the dining room)
- **Loose shared variables.** About 20 variables (current screen, drafts, timers) float around the shared space. Gather them into one "screen state" box with a single reset.
- **Four ways of wiring taps.** Move to one pattern: one listener per area, driven by a lookup table.
- **One pop-up helper** to replace the separately hand-built note/cardio/profile/plate panels. It also gives one place to fix pop-up accessibility (7.7).
- **Split the two biggest files** (`ui-views.js`, `ui-bind.js`) by screen: history, library, progress, settings, timers, viewport.
- **Copy-paste to merge:**

  | Repeated piece | Copies |
  |---|---|
  | Download code (JSON and CSV) | 2 |
  | Note panels | 2 |
  | "When did you finish?" panel | 3 |
  | Stat tiles | 4 |
  | Bar rows | 3 |
  | Set text formatting (one says "/hand", the others "/ea") | 4 |

- **Styling.** About 270 one-off inline styles. Turn the most repeated into named styles, and add a small spacing and font-size scale.
- **Dead bits:** `completedCardio`, unused CSS classes, six unused button IDs.

### Safety nets
| Add | Why | Size |
|---|---|---|
| **Duplicate-name check in `build.js`** | Stops the "one function silently replaces another" trap for good. | Small |
| **Test that the built files match the source** (including security hashes) | Can't ship a stale build. | Small |
| **Offline-worker tests** | That part is completely untested today. | Medium |
| **"Weird data doesn't blank a tab" test** | Protects against a bad import. | Small |
| **Speed guard at 2,000 workouts** (counts calculations, not time) | Keeps today's speed from quietly slipping. | Small |
| **Test for the one-time bodyweight stamp** | New code with no test. | Small |
| **Fake clock for timer tests** | 4 tests take 5–6 s each waiting on real time, and could fail randomly. | Medium |
| **A pre-commit check** (tests + build run before each save to git) | Nothing runs them automatically today. | Small |

### Deliberately not recommended
- **Shrinking the app file.** It's 117 KB over the wire and loads in milliseconds. Not worth adding a build tool you've avoided on purpose.
- **Rebuilding in React/TypeScript.** Too much churn for the gain. The cleanups above get most of the benefit.

## 9. Adding an AI coach

### What an AI coach could do here
- **"Ask your coach" chat:**
  - "Why has my bench stalled?"
  - "I have 35 minutes, what should I do?"
  - "Is my push/pull balanced?"

  The AI *looks up your actual numbers* by calling the app's own functions: your recent workouts, a lift's history, your PRs, weekly stats, your profile.
- **"Machine taken" swaps:** suggests an alternative that fits your gym profile.
- **Say or type it, it logs it:** "3 sets of 10 at 90 on the pec deck." iPhone dictation works in the box.
- **Post-workout recap and a weekly review:** a few sentences, generated once and saved.
- **Photo of a machine's label:** reads the weight step or the setup settings (the Claude version can accept images).

**Ground rules:**
- **Your data stays in charge.** The app's own math still decides progressions and PRs; the AI explains and suggests.
- **Nothing changes without you.** Anything the AI wants to change (add an exercise, change a weight) is shown to you to confirm, with undo.
- **Not medical advice**, same disclaimer as today.

### The catch
The home-screen app you use is a web page. It can only talk to the internet addresses its security settings allow; today that's just Dropbox (`build.js:58`). So there are four ways to add AI:

| Option | How it works | Cost | Effort | Downsides |
|---|---|---|---|---|
| **A. "Copy for Claude" button** | One tap copies a tidy summary of your recent training; you paste it into the Claude app and ask anything. | Free (your Claude plan) | **Small** | Not built into the app; a manual paste. |
| **B. Built into the Claude version** | The private Claude-artifact version of Ironlog can ask Claude directly. No server, no API key, and Claude can call the app's functions and look at photos. | Your Claude plan (it asks permission the first time) | Medium | Only works when opened inside Claude, not the home-screen app. It also keeps its own separate data (it can't reach Dropbox), so you'd switch to it as your main app or import your history into it. |
| **C. Built into the home-screen app via a tiny server** | A small free-tier cloud function (e.g. Cloudflare Worker) holds a Claude API key; the app calls it. | Pay per use; small for personal use (Haiku 4.5 for quick tasks, Sonnet 5 for coaching) | Medium–Large | A server to look after, and it needs a lock so strangers can't run up your bill. |
| **D. Type your own API key into Settings** | The app calls Claude directly with your key. | Pay per use | Small | **Not recommended.** Your key would sit in the phone's browser storage where a bad script could read it. |

### Recommendation
1. **Start with A** (an hour of work). Find out which questions you actually ask before building anything bigger.
2. If you like it and are happy to use the **Claude version** day to day, do **B**: the richest option with no server and no bills.
3. If you want it inside the **home-screen app**, do **C**, starting with read-only coaching (chat + recap) and adding "AI changes my workout" only with confirm + undo.
